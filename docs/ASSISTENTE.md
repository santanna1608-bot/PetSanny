# Assistente PetSanny

Versão escolhida pelo usuário: interpretação semântica via Jev (TypeSafe), resposta natural pela Responses API OpenAI (modelo padrão gpt-4.1-mini). Sem alterações ou envio automático. Agenda e pendências usam consultas limitadas ao tenant autenticado; nenhum cadastro ou prontuário é enviado aos modelos. OpenAI recebe apenas os indicadores agregados obtidos no servidor, referência do produto e conversa limitada; TypeSafe recebe a conversa para interpretar referências no pedido. A interface informa esse processamento e solicita não incluir dados pessoais. Histórico temporário em memória, até quatro mensagens anteriores por pedido, removido ao reabrir o painel ou mudar de clínica. Não há ferramentas de ação.

Profissional/Gold ativo e não vencido: 100 tentativas por mês, compartilhadas pela clínica. Teste válido: 10 tentativas ao todo, inclusive durante eventual extensão. Essencial, Crescer, teste expirado e clínica suspensa não acessam. Reserva atômica no PostgreSQL verifica associação ativa owner/admin/staff, plano, prazo e cota. RPC exclusivo do service_role. Tentativas que chegam ao provedor contam mesmo em caso de falha, limitando custos. Nenhum histórico de conversas é persistido.

Configuração: TYPESAFE_API_KEY e OPENAI_API_KEY somente como Secret no servidor Vercel (Preview para homologação, Production ao publicar); OPENAI_ASSISTANT_MODEL opcional, padrão gpt-4.1-mini. VITE_SUPABASE_URL e SUPABASE_SERVICE_ROLE_KEY já utilizados pelo backend. Não usar prefixo VITE para as chaves de IA. Migração 202610110014_assistant.sql aplicada e confirmada no Supabase. Sem chave ou migração, o endpoint falha explicitamente sem simular uma resposta. Requests OpenAI usam store:false e max_output_tokens:500. Tentativas falhas também consomem cota. A configuração store:false não substitui a política de retenção da API do provedor.

Validação: node --test tests/assistant.test.mjs; node scripts/validate-assistant.mjs com chave no ambiente; supabase/tests/assistant.sql com rollback.
